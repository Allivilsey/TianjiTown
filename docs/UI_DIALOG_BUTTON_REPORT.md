# TianjiTown 小镇 Dialog UI 实施报告

> 更新日期：2026-08-27  
> 适用版本：TianjiTown `1.4.0` / Paper API `26.2`  
> 实现位置：`tianjitown-paper/src/main/java/cn/tianji/town/paper/TownUiController.java`  
> 编辑说明：本文使用普通 Markdown；树形图和字符画均为纯文本，可直接增删节点。

## 1. 实施结论

小镇玩家界面已由“把旧箱子菜单压平成文字按钮”重组为以任务为中心的 Dialog：

- 主菜单只保留 5 个稳定入口：小镇资料、公共资产、成员治理、待办中心、个人与帮助。
- 资料、余额、费用、状态和规则改为常驻正文，不再伪装成无响应按钮。
- 原 `Material` 图标通过 `ItemDialogBody` 显示，名称和 lore 同时进入正文区。
- 普通导航使用两列 `multiAction`；危险操作使用原生 `confirmation`。
- 建镇申请、资料编辑、捐款、税率、Buff 时长、规则确认、管理员审核理由均使用原生输入控件。
- 成员、投票、小镇、入镇审核、管理员审核和账本均已分页，单页控制在 6～8 条。
- 表单输入不再借用公共聊天栏；聊天只保留系统通知和跨玩家确认按钮。

## 4. Dialog API 使用矩阵

| Paper Dialog 能力 | 当前用途 | 交互收益 |
|---|---|---|
| `ItemDialogBody` | 身份卡、资金摘要、规则、账本、危险操作后果 | 图标和关键信息常驻，不依赖悬浮 |
| `PlainMessageDialogBody` | 长规则、错误、说明、成功结果 | 长文本可直接阅读 |
| `TextDialogInput` | 名称、简称、领地名、捐款、审核理由 | 输入留在界面内，不占用聊天 |
| `MultilineOptions` | 简介、规则、补件要求、拒绝原因 | 适合结构化长文本 |
| `BooleanDialogInput` | 新规则已阅读确认 | 防止未阅读直接确认 |
| `SingleOptionDialogInput` | 初始成员、税率、Buff 时长 | 避免大量近似按钮和无效值 |
| `DialogType.multiAction` | 菜单和分页导航 | 固定两列，降低扫描距离 |
| `DialogType.confirmation` | 危险操作和表单提交 | 左右二选一语义稳定 |
| `DialogType.notice` | 加载、完整规则、成功结果 | 单一下一步，不制造假按钮 |
| `WAIT_FOR_RESPONSE` | 输入表单、确认框 | 等待处理期间保留上下文 |
| 一次性 `customClick` | 所有业务动作 | 防止双击重复提交 |

| 入口 | 普通成员 | 副镇长 | 镇长 | 管理员附加入口 |

| 小镇资料 | 是 | 是 | 是 | — |
| 公共资产 | 是 | 是 | 是 | — |
| 成员治理 | 是 | 是 | 是 | — |
| 待办中心 | 是 | 是 | 是 | — |
| 个人与帮助 | 是 | 是 | 是 | — |
| 审核入镇申请 | 否 | 是 | 是 | — |
| 修改简介和规则 | 否 | 是 | 是 | — |

主菜单不再把所有功能平铺。角色差异在二级页面内体现，待办数量在首页汇总。

## 6. 统一视觉与文案规则

| 语义 | 表现 |
|---|---|
| 页面标题 | 金色；标题描述当前任务，不写宽泛的“菜单” |
| 信息正文 | 白色主体、灰色辅助、金色对象或金额 |
| 普通动作 | 白色或金色，最多两列 |
| 成功 / 提交 | 绿色 |
| 警告 / 待办 | 黄色或青色 |
| 危险 / 拒绝 | 红色，仅用于会产生负面状态变化的动作 |
| 返回 / 取消 / 关闭 | 灰色；危险确认中的取消保持显眼 |
| 禁用项 | 转为正文并直接说明原因，不显示无响应按钮 |
| Tooltip | 只放补充说明；费用、状态和不可逆后果必须常驻 |

## 7. 已解决的问题

| 原问题 | 当前处理 |
|---|---|
| 资料卡看起来像按钮 | 无 action 的项目转为 Dialog Body |
| 图标在 Dialog 中消失 | 使用 `ItemDialogBody` 显示真实物品图标 |
| 重要说明藏在悬浮提示 | 名称和 lore 进入常驻正文 |
| 主菜单可达十余个入口 | 收敛为 5 个任务中心 |
| 45 条按钮堆成 15 行 | 动态列表改为 6～8 条分页 |
| 确认 / 取消纵向排列 | 使用原生 `confirmation` |
| 输入需要关闭界面去聊天 | 全部业务表单迁入 Dialog Input |
| Esc 后可能收到伪超时提示 | 会话到期改为静默清理 |
| 成功后只在聊天显示 | 捐款和 Buff 购买使用 Notice 展示结果 |

## 8. 后续建议

### P1：游戏内目视验收

需要在 Paper 26.2 客户端实际检查 `854×480`、`1280×720`、`1920×1080` 三档分辨率，重点观察长规则、长账本备注、输入焦点和滚动区域。源码编译无法替代这一项。

### P1：真实数据压力测试

使用至少 20 名成员、20 个小镇、20 条投票、20 条审核和 180 天账本数据检查分页边界。账本查询建议后续采用“每页数量 + 1”读取，以精确判断是否存在下一页。

### P2：拆分界面控制器

`TownUiController` 同时负责导航、表单、业务回调和文案，继续扩展会重新变乱。建议按以下边界拆分，但保持统一的 Dialog 基础设施：

```text
TownUiController
  TownDialogFactory        通用 Body / Button / Confirmation / Session
  ApplicationDialogs       建镇与资料表单
  GovernanceDialogs        成员、投票、转让、入镇审核
  FinanceDialogs           资金、税率、账本、Buff、扩张
  AdminReviewDialogs       管理员审核
```

### P2：移除旧槽位语义

当前 `MenuItem.slot` 只用于排序，`openMenu` 的 `size` 也只保留兼容调用。下一轮可改为显式的正文列表和动作列表，减少维护者把它误认为箱子 UI 的概率。

## 9. 验收清单

- [ ] 无镇籍玩家能完成三步建镇表单，错误值留在原表单并显示原因。
- [ ] 规则每行一条，保存后成员看到完整正文和勾选框。
- [ ] 捐款支持整数和合法小数，非法金额不会扣款。
- [ ] 税率单选默认选中当前值，保存后通知成员。
- [ ] Buff 时长选项显示价格、折扣和购买后等级。
- [ ] 账本、成员、投票、小镇、入镇审核和管理员审核翻页正确。
- [ ] 危险操作均显示对象、后果、确认和取消。
- [ ] 双击任何提交按钮只产生一次业务操作。
- [ ] Esc 关闭后不会延迟发送错误的“超时”消息。
- [ ] 低分辨率下正文可滚动、按钮不溢出、输入框可聚焦。
