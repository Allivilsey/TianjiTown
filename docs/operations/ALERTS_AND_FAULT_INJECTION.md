# 告警、故障注入与最终验收

所有故障注入只能在隔离预发服和生产数据副本执行。每个用例前创建同时间点备份，记录开始/结束时间、日志、诊断报告、数据库快照、玩家收支记录和 Residence 状态。

## 故障注入矩阵

| 故障 | 操作 | 必须结果 |
|---|---|---|
| Paper 重启 | 在投票结算、Buff 到期、返还计数后重启 | 不重复结算；状态恢复，信标重新发现并验证来源，旧历史效果不恢复 |
| SQLite I/O 失败 | 在克隆环境撤销文件写权限或耗尽专用测试卷 | 新写入和返还锁定，Residence 保护保持；恢复后可诊断/继续 |
| Residence 丢失 | 移除测试镇投影后执行自动/手动对账 | 按最新 SQLite 领地与成员记录重建并保留 ACTIVE 状态；修复有审计且不覆盖同名外部领地 |
| Vault 失败 | 暂停 Economy provider 或使玩家扣款调用失败 | 玩家扣款失败不增加小镇余额；未知结果保留核实记录，不重复付款 |
| QuickShop 回滚 | 触发失败/取消交易并重放成功事件 | 失败不入账，同一成功事件只入账一次 |
| 依赖不可用 | 分别移除/禁用必需依赖启动 | 启动门禁 `LOCKED`，现有数据不被重写 |
| 信标来源与自然消退 | 切换效果、遮挡光束、拆金字塔、拆信标、卸载区块，再离开或归档领地 | 失效来源停止续期，已有药水效果按原版时长自然消退；区块恢复运行后重新验证 |
| 返还竞态 | 概率 100%、并发快速放置并跨重启 | SQLite 按小镇/玩家/周的原子上限不超发；特殊/自动放置为零 |

## 最终验收记录

- [ ] 玩家没有小镇命令，只通过服务台/手册完成所有玩家流程。
- [ ] 管理员能审批、代办、对账、修复和诊断每类操作。
- [ ] 并发申请/扩张/消费/投票/返还均保持唯一与幂等。
- [ ] 统一报告可定位 SQLite、Residence 和公共账本异常。
- [ ] 所有高风险操作可审计、可重试且不会重复扣款或入账。
- [ ] 重启和六类故障注入全部通过，没有 ACTIVE 无保护小镇。
- [ ] 当前初始结构建库、Flyway 完整性校验、隔离恢复及整套 JAR/数据回退通过；结构不匹配时已有数据库保持不被删除或重建。
- [ ] 大成员列表分页、完整历史账本、规则/税率告知和基础资料 SQLite 单一入口通过。

完成后将报告、日志、版本、配置脱敏副本、备份清单和 SHA-256 保存到发布档案；只有上述全部验收项目都有证据时才能通过生产门槛。
