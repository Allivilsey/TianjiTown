# 领地加成部署与验收

适用于 `1.0.0-SNAPSHOT`。建筑返还和信标记录来自当前初始数据库结构，没有历史升级或数据回填步骤。默认配置见 [配置说明](../setup/CONFIGURATION.md)。

## 建筑返还

本镇成员在本镇有效 Residence 内，以生存模式放置合格单方块，默认 25% 概率返还一个同种方块；成功仅播放拾取音效，不展示内部额度。背包满时物品掉在玩家身边。

内部按“小镇、玩家、周”计数，默认每组每周 3000 次，按 `reset-zone` 的周一 00:00 切换，默认上海时间。旧计数保留 12 周；这不影响永久公共账本。

隔离验收时把概率改为 `1.0`、上限改为 `2` 并重启：

- 同一成员在本镇合格放置恰好返还两次，另一个成员单独计数；重启不重置本周额度。
- 镇外、他镇、创造、访客、自动或多方块放置不返还。
- 容器、床/门、信标、活塞、黏液块、带元数据物品及黑名单材料不返还。
- SQLite 故障不绕过额度；恢复后重新验证。验收结束恢复部署参数并重启。

## 领地信标

镇长或副镇长在有效信标中设置效果并关闭界面时，系统把新增效果或更高等级保存到数据库。之后按玩家位置刷新到整个小镇有效 Residence，默认每 100 tick 一次。进入者不必有本镇成员身份。

系统不扫描已加载区块，不持续依赖原信标存在；拆掉信标、破坏金字塔或卸载来源区块都不会删除已记录效果。离开有效领地、归档、关闭功能或停用插件时清理玩家托管效果；关闭开关不删除数据库效果记录。

验收以下行为：

1. 镇长/副镇长可打开信标，普通镇员、访客和他镇管理员不能以本镇管理者身份编辑。
2. 在本镇有效信标记录效果，远离原版信标范围但仍在本镇领地时可以获得，镇外不获得。
3. 记录另一种效果和更高等级；同类仅保留最高等级，低等级不能覆盖高等级。
4. 拆除来源信标并重启，已记录效果仍可恢复；离开领地或归档后清理。
5. `territory.beacon.enabled: false` 后 `reload`，托管效果清理；重新开启后依据记录恢复。

## 诊断与数据恢复

`diagnose [天数]` 同时检查 SQLite 完整性及业务异常、Residence 投影、Vault 清算和 QuickShop 历史，报告保存在插件目录 `diagnostics`，保留最近 30 份。它不在线备份、不自动修复，历史核对的范围和限制见 [命令手册](../ADMIN_COMMANDS.md)。

部署前备份并完成隔离恢复，详见 [SQLite 手册](../operations/SQLITE_AND_BACKUP.md)。故障注入见 [验收矩阵](../operations/ALERTS_AND_FAULT_INJECTION.md)。不要为切换构建而删除、重建或手工改写已有数据库。
