# 成员治理部署与验收

适用于当前 `1.0.0-SNAPSHOT`，数据库仅维护初始结构。角色为 `MAYOR`（镇长）、`DEPUTY_MAYOR`（副镇长）、`MEMBER`（镇员），没有 OFFICER 角色或角色迁移步骤。

## 治理规则

| 流程 | 规则 | 验收重点 |
|---|---|---|
| 副镇长任免 | 镇长操作，最多 3 人 | 超额任命、重复操作、非镇长操作被拒绝；降职后管理权失效 |
| 移除成员 | 镇长可移除非镇长成员；副镇长只能移除普通镇员 | 不得通过普通移除入口移除镇长或越权处置副镇长 |
| 访客管理 | 镇长/副镇长添加或移除 | 只有领地访问权，没有镇籍、投票、税务归属或成员公共 Buff；访客入镇后合并身份记录 |
| 镇长转让 | 候选成员在 24 小时内明确接受 | 原镇长降为普通成员；拒绝、到期、目标离镇或重复接受不能产生两个镇长 |
| 规则与税率通知 | 变更后在登录或菜单提示 | 新规则确认前不能继续普通菜单流程；税率说明与实际值一致 |
| 移除成员投票 | 所有成员可发起，目标为非镇长成员 | 排除目标，赞成票严格超过有效选民 50% |
| 更换镇长投票 | 镇长/副镇长可发起，候选人为非镇长成员 | 排除现任镇长，赞成票达到有效选民 2/3，向上取整 |
| 发起人终止投票 | 发起人在详情页二次确认 | 只能终止自己仍为开放状态的投票，取消不执行提案结果；他人或已结束投票被拒绝 |

投票创建时冻结最近 30 天活跃选民，不额外要求入镇时长，持续 72 小时。同镇任何时刻只能有一个开放投票；每个 UUID 一票，全员投完或到期才结算。发起者通常须在冻结选民名单内；现任镇长发起更换镇长投票时例外，可以发起但不获得该次选票。管理员身份不跳过玩家界面的镇籍、角色或选民限制。

## 管理员代办

完整语法见 [命令手册](../ADMIN_COMMANDS.md)。`member add/remove/role` 和 `mayor transfer` 是直接人事调整；投票通过玩家 GUI 发起并自动结算，没有管理员发起投票的独立命令。`vote cancel <小镇代码> [原因]` 取消该镇当前开放提案，不执行提案结果；省略原因时使用“管理员调整”。

分别核对数据库成员角色、Residence 权限、在线公共 Buff 和身份通知，确认这些入口不会遗漏同步。管理员接任不要求候选人接受，玩家接任需要双方确认。

## 并发和恢复

- 并发发起不同类型投票，只有一个开放投票成功。
- 镇长可发起换届但不能给该提案投票；副镇长仍须满足选民条件，普通镇员即使有管理员权限也不能从玩家界面发起换届。
- 发起人取消自己的投票后，旧选票不能继续提交；他人取消、重复取消或取消已结算投票应拒绝。
- 全员投票与后台到期结算竞态，只执行一次人事变更和审计。
- 投票期间目标离镇或角色变化，结算不能执行失效的人事结果。
- 关闭或重启后，投票、接任请求和待投递通知保持可恢复。
- 归档保留成员历史、资料和审计，Residence 清理成功后才释放名称及区块。

运行 `mvn -B clean verify` 后，还需按 [测试入口](../../test/README.md) 完成真实服务端验收。恢复时使用同时间点的整套备份，不给当前数据库套用历史 schema 升级或降级脚本。
