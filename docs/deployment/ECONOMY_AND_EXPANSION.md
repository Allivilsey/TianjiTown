# 公共经济与领地激活部署验收

适用于 `1.0.0-SNAPSHOT`。当前 QuickShop、Jobs、GlobalMarketPlus 共用小镇税率和补贴额度；数据库只维护初始结构，不提供历史开发版本的升级步骤。

## 经济接入

| 收入来源 | 税务归属 |
|---|---|
| QuickShop SELLING | 收款的商店所有者所属小镇 |
| QuickShop BUYING | 与商店交互、实际收款的玩家所属小镇 |
| Jobs | 获得工资的玩家所属小镇 |
| GlobalMarketPlus | 获得成交收入的玩家所属小镇 |

非成员收入不收小镇税，其他未接入 Vault 转账不征税。初始税率 5%，可设为 5%～25% 的整数百分比。税额按 Vault provider 的货币精度处理。

QuickShop-Hikari 税务接入要求至少 `6.3.0.0` 且事件、税款接收方和交易账户 API 能力通过。接口不匹配会报告并停用对应动态税务接入；检查 `status` 和日志，不要只看依赖已安装。QuickShop 税款接收方切换到专用清算账户，成功交易后写小镇分账。

## 部署准备

1. 按 [备份手册](../operations/SQLITE_AND_BACKUP.md) 在同一停服时间点备份 TianjiTown、Residence、QuickShop、XConomy，记录清算余额，在隔离服验证。
2. `economy.settlement-account` 默认 `tax`，通过 Paper 离线玩家 UUID 与实际名称大小写访问；确保专用且没有其他插件擅自清理或分配该账户资金。
3. 检查 QuickShop 固定税或其他经济插件的独立税收规则，避免同笔交易重复征税或混入无法归属的清算金额。
4. 启动后执行 `status`、`diagnose 7`，核对接口状态、外部余额、内部余额和诊断报告。

## 税收与补贴验收

每组交易核对玩家余额、交易结果、外部插件记录、清算余额、小镇余额及账本。

- 分别验证 QuickShop 出售/收购、在线/离线店主、Jobs 工资、GlobalMarketPlus 成交和非成员交易。
- 失败、取消、库存不足和余额不足的交易不能生成成功税款；重复事件不能重复入账。
- 三种收入共用每镇每周 `10000.00`、每 12 小时 `2000.00` 补贴上限。单笔提供等额补贴，额度不足时部分补贴，耗尽后仍入税款。
- 固定上海时间周一 04:00 和每日 04:00/16:00 切换补贴窗口；重试沿用首次预留周期。
- 账本按每日 04:00 分日，Jobs 显示职业收入，QuickShop/GlobalMarketPlus 显示商店收入；税款和实际补贴正确汇总，底层明细保留。

QuickShop 诊断只核对本地已记录税款对应的历史，不能发现全部外部漏记，也不能证明历史收款账户。查询异常或达到 1000 条扫描上限标记 `INCOMPLETE`。Jobs 与 GlobalMarketPlus 不属于这项 QuickShop 历史逐笔核对，需另查对应收入记录。

## 公共资金和补偿

- 测试整数、小数捐款，个人扣款、清算入账与内部账本应一致。
- 清算入账失败应退款；退款失败在当前运行期最多重试 8 次，按 1、2、4、8、16、30、30、30 秒退避。成功后还要清算复核；超过上限或中途停服转人工核对，不重复补账。
- `money adjust` 正负调账同时改变清算余额和内部余额，记录原因及操作者；它不能仅修正外部短款。
- 清算短款锁定新的公共消费；捐款和查询仍可用，但若管理员关闭消费总开关，捐款也暂停。补正后等待后台清算对账，再检查账户锁定状态。
- 成员可分页查看完整历史，管理员 `ledger view` 仅展示最新 45 个项目。

## 领地激活

审批通过后，小镇立即获得以初始区域为中心的 5×5 单元网格，共 25 个区域（每区域 5×5 区块，合计 400×400 方块）。初始区域自动激活并拥有完整小镇 flag；其余 24 个区域仅禁止创建、追加、调整或设立子领地，其他行为与野外一致。激活区域必须与已激活区域保持四方向连通。首块默认 `5000.00`，第 n 次价格为 `5000 × 1.05^(n-1)`，每块向上舍入后求和；详见 [定价](PRICING.md)。

验证单格和批量选择、报价变化、非相邻/越界拒绝、WorldBorder 缓冲、余额不足、区块冲突、并发确认、Residence 失败退款及重启恢复。数据库内扣款与占位同事务，投影失败需释放占位和退款。

未激活区域由小镇预留索引阻止圈地，不创建带有默认 flag 的 Residence；重启从数据库中的小镇初始区域恢复预留范围。数据库 territory_units 记录已激活区域，全部归属范围由初始区域确定。激活成功后才加入 Residence area，失败退款并撤回新保护，预留归属不受影响。删除小镇时释放预留。

Residence 每个 area 水平为 80×80 方块，最大坐标为最小坐标 +79。不能只凭 Residence 局部可视化判断区域缺失；结合小镇领地预览、`land reconcile`、area 列表和实际权限测试。激活预览和购买通过镇长地图完成。

## 暂停与恢复

把 `economy.tax.enabled`、`economy.consumption.enabled` 设为 `false` 后执行 `reload`，分别停止新税收与捐款/激活等新消费入口；已提交退款、恢复和查询仍可进行。维护模式本身不停止税务和后台任务。涉及回退时停服保留当前副本，使用已验证的整套备份恢复，不将旧 JAR 直接指向未知结构数据库。
