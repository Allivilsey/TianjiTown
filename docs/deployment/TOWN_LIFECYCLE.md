# 建镇与成员部署验收

适用于 `1.0.0`。批准后立即预留完整 5×5 区域网格；每个区域为 5×5 区块，初始区域自动激活完整 flag，其他区域保持野外行为并禁止圈地，后续付费激活。建镇需两名初始成员确认，后续采用入镇申请制。完整语法见 [管理员命令](../ADMIN_COMMANDS.md)，字段限制见 [功能说明](../FUNCTIONS_AND_GAMEPLAY.md)。

## 准备

按 [安装检查](../setup/PREFLIGHT.md) 准备依赖、WorldBorder 和独立测试数据库。使用一名申请人、两名无镇籍初始成员、一名后续入镇玩家及管理员；普通流程应使用无管理员权限的账号验证。

## 申请和创建

1. 从讲台领取手册，分别验证两种入口；自行重复领取应受默认 60 分钟冷却限制。管理员命令可连续发放，且不刷新玩家自行领取的冷却时间。
2. 填写名称、3～9 位英文字母代码、简介和规则；更换/清空初始成员并保存草稿，确认此时不发邀请。
3. 完成资料并发送邀请，两名成员分别测试接受、拒绝和重新提醒；只有最终两人都接受且仍无镇籍时才能提交。任一人拒绝后，重开申请应直接进入成员选择，保留资料与有效选址；重新发送后两人都须确认，旧邀请失效且旧提醒冷却清除。
4. 选择区块，验证整镇 25×25 区块（625 区块）的碰撞与边界检查，以及初始 5×5 区块的火焰预览和中心传送。即使中心 5×5 区块合法，整镇外围与缓冲越过 WorldBorder 或与其他领地/预留冲突时也应拒绝；临时预留默认覆盖整镇 60 分钟。
5. 在 GUI 中使用不同测试申请分别验证退回修改、拒绝和批准，每次填写明确原因。退回修改可重新编辑，拒绝/撤回后再申请有冷却。
6. 批准后核对申请人扣款、镇长和两名普通成员、公共初始余额、整镇 625 区块归属及初始 25 区块的全高度 Residence 保护；其余 24 个单元只预留并禁止圈地，尚未加入 Residence area。默认申请费 `5000.00`，代码 `SKY` 对应 Residence `sky`。

## 入镇与领地访问

- 建镇后的新成员通过入镇申请加入，镇长/副镇长审批；测试最多 3 份、48 小时有效、同镇拒绝 24 小时及主动离镇 24 小时冷却。
- 验证成员与访客获得 Residence trusted 权限及额外点火/载具破坏权限，离镇或移出访客名单后撤销。
- 验证小镇 `monsters=false`、`nomobs=true`；怪物进入保护需要 Residence 开启 `AutoMobRemoval`。
- 镇长将手册放上空讲台，确认建立绑定本镇的服务台且每镇限一个，数据库和讲台标识重启后保持一致。

## 并发、恢复与删除

- 同一申请并发批准，只能收取一次成功建镇费用并创建一套小镇数据；重叠选址不能同时占用。
- Residence 创建失败时检查失败状态、补偿和重试，不得出现静默成功的无保护小镇。
- 执行 `land reconcile <小镇代码>` 只读检查，显式加 `repair` 后修复；系统自动对账应按 SQLite 最新记录恢复，不覆盖同名外部领地。
- 执行 `town delete <小镇代码> <原因>` 并确认：先归档，Residence 清理成功后才释放名称、代码和区块。清理失败保持占位，排障后可重新发起删除完成释放。
- 重启后核对申请、预留、成员、访客、服务台和领地恢复；测试确认按钮过期、重复点击及目标版本变化时不能误执行。

首次建库依次执行 `V1_0` 和 `V1_1`；正式服 schema `1.0` 通过一次增量迁移升级到 `1.1`，保留余额和历史流水。不提供 YAML 小镇镜像导入或 MySQL 自动转换。已有数据库必须先保留副本，不能为通过校验而删除或重建。数据恢复见 [SQLite 手册](../operations/SQLITE_AND_BACKUP.md)。
