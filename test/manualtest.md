# TianjiTown 最小 P0 人工证明集

适用版本：`1.0.0-SNAPSHOT`。本文件是**常规候选发布的人工执行清单**，所有项目初始为NOT_RUN。压缩依据、137个子项的分类及旧→新映射见[压缩审查](P0_COMPRESSION_REVIEW.md)；故障、兼容性及可选功能见[条件专项](P0_SPECIAL_TESTS.md)。旧清单仅作历史参考，不再重复执行。

## 发布门槛

常规人工通过 + 候选基线自动测试通过 + 本次触发的专项通过，才可验收。FAIL、BLOCKED、NOT_RUN都不是PASS。首次建立发布基线或缺少适用专项成功证据，须建立专项基线；不能因移出了常规smoke就宣称恢复风险已被证明。

本清单保留真实建镇、三方资金、独立税适配器、独立授权、实际领地保护、身份与正常重启。价格/输入组合、确认码时间、4选民阈值、补贴跨窗交自动化，仍是上线阻断检查，不再要求人工枚举。

2. 保存commit/未提交变更、候选JAR哈希、Java/客户端/服务端/依赖版本。安装Residence、Vault、XConomy、WorldBorder、QuickShop-Hikari、Jobs、GlobalMarketPlus，核实Vault provider及本轮实际API能力。
3. 角色沿用Z/Z2管理员，A/D/M建甲镇，B/B1/B2建乙镇，J待入镇，V访客，G无镇籍对照。普通角色无OP/管理/Residence绕过权限，生存模式；记录实际UUID。代码使用`pzeroa`/`pzerob`，用实际名称替换命令中的代号。
4. 两个合法区域X/Y和野外对照均避开出生点保护等其他规则。整镇预留25×25区块，两轴为中心区块±12，再满足WorldBorder缓冲。准备石块/普通箱子、商店/市场物品、Jobs付费行为；依赖命令以本服帮助核实，不猜版本语法。
5. 保存**拟上线的有效配置**：F申请费、货币精度s、清算账户UUID/名称、激活base、health价格、税补贴额度/周期、功能开关。下列默认路径假定公开消费/Buff/税收开启；如决定关闭，按专项文档的关闭条件处理，不能未经测试仍沿用默认开启。
6. 补钱、建立B镇对照、任命测试副镇长、创建商店、存S1均为夹具；用正常已验证入口，所有余额变化仍记入统一账目。每次写操作前后记录P（相关玩家）、T（目标镇）、S（外部清算）、另一镇余额与业务ID/流水。截图/日志/账本观察与该交易一起判定，不另计一项。
7. 玩家必须实际通过讲台/手册/Dialog，命令代办不替代玩家流程。省略前缀的本插件命令均加`/tianjitown `，控制台去掉最前的斜杠。税展示按日汇总，核对底层逐笔记录和第三方交易历史，不能只数界面行。
8. 暂停非测试交易。普通写操作观察最多60秒，启动180秒；后台任务等待本轮周期+30秒。超时先查操作ID和资金，不盲重付。竞态由两个真人客户端同时提交并记录重叠证据；若实际串行，只能记串行结果并重做该竞态，不能用聊天时间接近冒充。
9. 自动门槛：同一候选源码执行`mvn -B test`，确认[审查文档E01～E19](P0_COMPRESSION_REVIEW.md)中转自动的具体断言通过；不拿文件名存在作为PASS。

### 统一账目断言

`ceil_s`表示按有效货币精度向上取整。实际配置和独立计算结果是预期来源，界面报价只作对照。关闭或单列第三方原生手续费。

| 操作 | 预期 |
|---|---|
| 建镇费F | 申请人ΔP=-F，新镇T=F，ΔS=+F；两初始成员P不变 |
| 捐款d | ΔP=-d，ΔT=ΔS=+d |
| 管理调账d | ΔT=ΔS=d；普通玩家P不变 |
| 公共消费c | ΔT=ΔS=-c；操作者P不变；资产/效果仅与成功交易对应 |
| 已付费激活n格，再买k格 | c=Σceil_s(base×1.05^(n+i))，i=0…k-1；中心不计付费次数 |
| Buff w周L级 | c=ceil_s(basePrice×w×[1-0.05×(w-1)]×L) |
| 税前收入g、税率r | 选可整除样本：税t=g×r，补贴u=min(t,周剩余,12小时剩余)，收款净额g-t，ΔT=ΔS=t+u |
| 拒绝/取消/重放 | 无新增业务副作用；有失败补偿时必须解释所有差额，不能静默记PASS |

## 执行顺序

完成一轮执行后，将对应步骤的 `[ ]` 改为 `[x]`，并在“完成反馈”填写 `PASS` / `FAIL`、实际结果及证据位置；勾选只表示已执行，不代表通过。未执行或阻塞时保留 `[ ]`，反馈填写 `NOT_RUN` / `BLOCKED` 及原因。反馈较长时可填写报告中的对应步骤链接。

01～09继承正常状态；10正常重启后存完整S1。11短款分支、12删除分支分别从S1复制**整套数据**，不单独回滚SQLite。所有破坏性专项同样从S1分支。夹具准备不要求额外真人重新证明已经通过的机制。
