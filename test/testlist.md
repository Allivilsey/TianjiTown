# TianjiTown 功能与玩法测试列表

> 适用版本：TianjiTown `1.4.0`，配置 schema `10`，Flyway schema `1.0`，Paper API `26.2`
>
> 整理基线：`0c1cdca`，更新日期：2026-08-29
>
> 依据：当前 `README.md`、`docs/FUNCTIONS_AND_GAMEPLAY.md`、默认配置、消息文件及实际业务/UI 代码

本文件是当前版本的统一功能验收入口，覆盖玩家可见玩法、管理员支撑功能，以及会影响资金、领地或玩家状态的故障恢复。历史自动化报告只作为参考，不代表本清单已经通过；每轮测试应从空白状态重新记录。

## 0. 使用说明

### 0.1 状态与优先级

- `[ ]`：未执行；`[x]`：通过；`[!]`：失败；`[-]`：阻塞或本轮不适用。
- `P0`：发布阻断项，涉及入口可用性、权限、资金、领地保护、幂等或数据恢复。
- `P1`：核心玩法与主要回归项。
- `P2`：体验、显示、容量或较低风险兼容项。
- 只有操作步骤全部完成且预期结果全部满足，才能把状态改为 `[x]`；部分通过仍按失败或未完成记录。

### 0.2 每轮必须记录

```text
测试轮次 / 日期：
分支 / 提交：
JAR SHA-256：
Paper / Java：
配置 schema / Flyway schema：
Residence / Vault / XConomy / WorldBorder：
QuickShop-Hikari / Jobs / GlobalMarketPlus：
测试服务器 / 世界 / 时区：
执行人 / 复核人：
通过 / 失败 / 阻塞 / 未执行：
缺陷编号：
截图、录像、日志、余额和数据库证据位置：
结论：发布 / 不发布
```

资金用例至少核对玩家余额、Vault 清算账户、小镇公共余额和账本；领地用例至少核对实际 Residence 边界、成员权限、地图显示和重启后的状态。强制停服、依赖故障、数据库故障、恢复和并发破坏性用例只能在隔离测试服执行。

### 0.3 建议账号与数据

- 管理员 A：OP/完整 `tianjitown.admin`；管理员 B：用于并发审批和分项权限测试。
- 小镇甲：1 名镇长、3 名副镇长、至少 4 名普通成员；同时准备活跃与 30 天未活跃成员。
- 小镇乙：1 名镇长、1 名成员，用于跨镇、相邻领地和访客测试。
- 至少 5 名无镇籍玩家，其中 2 名在线初始成员、1 名离线玩家、1 名低余额玩家、1 名背包已满玩家。
- 准备矩形与椭圆 WorldBorder、黑名单区域、普通 Residence、相邻小镇、平地/高山/低洼地形，以及余额正好等于费用和余额不足的数据。
- 为概率玩法使用可临时调整的隔离服配置验证命中与不命中，再恢复默认值复测一次。

### 0.4 最小 P0 冒烟路径

发布候选至少完成：`SYS-01`、`ENTRY-01`、`UI-04`、`APP-09`、`APP-14`、`APP-18`、`MEM-07`、`GUEST-03`、`GOV-06`、`ECO-02`、`ECO-11`、`LAND-01`、`LAND-09`、`BUFF-05`、`REFUND-01`、`BEACON-05`、`ADM-07`、`SAFE-02`。任一项失败时不得发布。
